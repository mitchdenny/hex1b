# HEX1B0011: Declare one top-level type per file

Each source file in the main Hex1b library must contain at most one distinct
top-level type. Keeping types in separate files makes changes easier to review.
The rule reports an error on each additional type's name.

This includes classes, structs, records, interfaces, enums, and delegates,
regardless of accessibility. Types in different namespaces still count as
distinct types in the same file. Generic and non-generic types with the same
name are also distinct.

## Exceptions

- Nested types stay with their containing type.
- Generated files are excluded using Roslyn's generated-code detection.
- Multiple partial declarations of the same type are allowed, within one file
  or across files.
- Inactive conditional-compilation branches do not count toward the active
  file's type declarations.

## Fix

Move each additional top-level type into its own file, normally named after the
type. Preserve its namespace, accessibility, attributes, documentation, required
using directives, and conditional-compilation context. Do not make a type nested
merely to bypass the rule, since that changes its identity and may break callers.

## Scope and distribution

The diagnostic has error severity but is disabled by default.
`src/Hex1b/.editorconfig` enables it for the main library only; tests, samples,
and other repository projects are not required to follow this rule.

The existing repository-local analyzer project reference uses
`OutputItemType="Analyzer"`, `ReferenceOutputAssembly="false"`, and
`PrivateAssets="all"`. The analyzer project is not packable. Neither the analyzer
nor this configuration is distributed to consumers of the Hex1b NuGet package.
